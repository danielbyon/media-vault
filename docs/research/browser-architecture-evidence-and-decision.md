# Browser architecture: evidence and decision

Date: 2026-10-12  
Decision: **retain visible WKWebView for v1; separate ordinary downloads from explicit Save to Vault; converge accepted acquisition receipts at the existing authenticated MediaLibrary journal.**  
Architecture decision records: [visible browser](../adr/0001-retain-wkwebview-visible-browser.md) and [acquisition/ingestion](../adr/0002-separate-browser-downloads-and-vault-acquisition.md).

## Why the choice matters

Browser is a first-class authenticated acquisition destination, but must remain a normal multi-tab browser. Existing production BrowserFeature already owns TCA tab state, popups, app-owned Start Page, persistent-private/ephemeral data-store selection, URL-only tab persistence, WebKit snapshots, keyboard-aware refresh, and a page-to-card transition. No browser library evaluated in September replaced that product-specific shell without a fork, substantial dependencies, or state-model duplication. The SwiftUI WebPage proposal offered simplification but required behavioral parity before deleting the existing WKWebView adapter.

The product also distinguishes [ordinary downloads (#42)](https://github.com/danielbyon/media-vault/issues/42) from [explicit Save to Vault (#43)](https://github.com/danielbyon/media-vault/issues/43). The [single durable journal (#13)](https://github.com/danielbyon/media-vault/issues/13) is implemented; [background protected receipt and authenticated reconciliation (#17)](https://github.com/danielbyon/media-vault/issues/17) remains open, with [session privacy/auto-lock (#9)](https://github.com/danielbyon/media-vault/issues/9) an open prerequisite. The production MediaLibraryClient exposes a Files-oriented importFile(URL), not an accepted-receipt interface.

## Consolidated experiments

Findings are from Xcode/iOS 27 SDK inspection, iPhone 17 and iPad Pro 11-inch (M5) simulator fixtures, and—where stated—a physical iPhone 17 Pro Max (iOS 27.0.1). PASS applies only to the measured case, not the entire issue.

| Research | Finding | Result and architecture consequence |
| --- | --- | --- |
| Open-source browser libraries (Sep 29) | Mozilla BrowserKit, DuckDuckGo modules, and small wrappers do not replace app-owned TCA tab/session/UI semantics without significant packaging or policy costs. | **Not chosen.** Preserve BrowserFeature's existing domain. |
| WebPage/WebView feasibility (Sep 29) | SwiftUI API could simplify navigation/KVO, but site-created windows, exact viewport snapshots/transitions, keyboard-refresh arbitration, and PiP restrictions lacked parity proof. | **Migration unapproved.** Acquisition became a mandatory gate. |
| Spike 1: public WebPage downloads (Oct 8) | Returning .download is observed for download attribute, attachment, unsupported MIME, redirects, cookie attachment, and blob fixture, but public iOS 27 WebPage lacks an app-owned WKDownload/destination/progress/completion file handoff. | **FAIL** for ordinary download lifecycle: a page navigation policy is not a file receipt. |
| Spike 2: WebPage to background URLSession (Oct 8–9) | Bytes matched for multiple GET, cookie, redirect, and lifecycle fixtures; a manually added Cookie header crossed an origin-changing redirect, response-triggered one-time URL replay failed, blob was unavailable; actual system relaunch unverified. | **PARTIAL.** Do not use credential/header replay for general browser downloads or authenticated Save. |
| Spike 3: never-mounted companion WKWebView WKDownload (Oct 8–9) | Public download callbacks and same-origin redirect blocking worked for the tested GET; identical WKWebsiteDataStore did not confer HttpOnly-cookie parity, POST body/signed-response/blob/resume paths did not reproduce originating page semantics. | **PARTIAL.** Do not treat a companion as the originating WKWebView or as a general-purpose bridge. |
| Spike 4: explicit Save to Vault (Oct 9–10) | Explicit fixture links/direct still URL generated byte-identical still receipts; MP4 was receipt-only. iPhone direct-video Save control was not hittable. A test-only copy entered the real SQLite journal and committed one still asset. Cookie-authenticated companion download failed. | **PARTIAL.** Safe direct request subset is feasible; genuine UI selection and production receipt acceptance are not proven. |
| Spike 5: long-press selected inline media (Oct 10–11) | Native image menus appeared, but SwiftUI webViewContextMenu(menu:) is unavailable on iOS in the installed 27 SDK. Genuine long presses produced no script contextmenu message; touch/pointer diagnostics are not selected-media evidence. | **Unsupported** through the tested SwiftUI paths. Do not infer unlinked image/video URLs from network traffic or DOM scans. |
| Spike 6: protected receipt, lock/relaunch (Oct 11–12) | Exclusive protected descriptor, sync/publish, opaque metadata, failure checkpoints, and a test-only SQLite handoff passed focused and completed simulator matrices. A physical iPhone received 8,388,690 bytes while the device was operator-confirmed locked; the individual receipt/directory reported NSFileProtectionCompleteUnlessOpen, with matching byte count/hash and post-unlock verification. | **PARTIAL.** Locked receipt creation is supported; closed-file access while locked, locked fresh-process, physical canonical .complete, genuine OS relaunch, and production authenticated handoff remain unverified. |

**Validation accounting:** Spike 6 has two complete corrected two-device simulator runs. A later last-source iPad attempt passed five UI assertions but timed out collecting Xcode diagnostics before its package command, and its two retries did not reach XCTest; it is *not* a completed final-source iPad matrix. The physical lock test is independent of simulator and manual lock evidence must not be described as an OS-initiated relaunch. Evidence exports are sanitized and omit raw xcresult bundles/system-owned URLSession state.

## Selected module seams

    BrowserFeature / TCA (authoritative logical tabs, profile and UI policy)
           |
           v
    BrowserWebKitClient -> @MainActor originating WKWebView for each live tab
           |
           +-- ordinary WebKit navigation/download -> WKDownload
           |      -> operation-scoped transient scratch -> preview/share/discard (#42)
           |      -> never implicit MediaAsset
           |
           +-- explicit user-selected Save to Vault intent (#43)
                  -> eligible anonymous HTTP(S) GET? -> background URLSession
                  -> protected app-controlled receipt + opaque manifest (#17)
                  -> authenticate/unlock -> one MediaLibrary journal (#13)
                  -> validate / duplicate+quota decisions / canonical .complete commit
                  -> cleanup receipt after permanent-state verification

This diagram describes ownership, **not an implemented production pipeline**. A WebKit-originated download might also be considered as a future media-acquisition input, but only after the originating WKWebView's actual transfer handoff and user authorization are tested. The browser does not own an alternative SQLite store, canonical asset metadata, or a permanent Downloads directory.

## Behavioral and security decisions

1. **Visible browser: WKWebView.** Keep current per-tab WebKit owner, TCA state, Start Page, session privacy, URL-only restoration, popup semantics, snapshot/zoom transitions, and refresh/keyboard behavior. Do not pursue an iOS 27 SwiftUI WebPage migration merely to reduce adapter code.
2. **Ordinary downloads: WebKit-native.** Implement #42 on the *originating WKWebView* using public WKDownload/Delegate and transient scratch. The public interface is documented, but this project's origin-webview attachment/post/body/blob/credential fixture matrix is still a future validation gate. Do not claim full parity from the companion spikes.
3. **Explicit Save: narrow and opt-in.** User selection must be real and tied to one resource. Only the supported anonymous, idempotent HTTP(S) GET subset qualifies for background URLSession. No Cookie/Authorization copying, POST replay, one-use token replay, blob/data extraction, DRM bypass, or page-wide scanning. Automatic background redirects do not permit per-hop credential stripping; deny/fail unsupported cases rather than claiming equivalent browser-session semantics.
4. **Receipt versus canonical commit.** A durable app-controlled receipt is not a Library asset. Protect bytes under .completeUnlessOpen and store only opaque recovery identity/minimal digest/size before unlock. After authenticated access, one production MediaLibrary seam must reconcile into the existing journal and canonical .complete resources; only completed assets become visible. Test-only @testable insertion is not production acceptance.
5. **Context-menu scope.** UIKit WKContextMenuElementInfo.linkURL is a public link destination, not a selected image/video source. Link-specific long-press Save may be designed against this public surface, subject to runtime and validation; unlinked inline media remains unproven and is not silently dropped from #43 acceptance. Do not treat Spike 4's synthetic vault-save fixture links as native menu proof.
6. **Ephemeral browsing.** Explicitly requested Save creates a separate durable acquisition, but the app may not retain ephemeral cookie, page-state, or tab-history metadata in its own receipt records. System-managed background URLSession may retain the URL while running; document the exception during privacy review and test profile switches and locking.
7. **Backups and diagnostics.** The disposable Spike 6 receipts requested backup exclusion and checked the value after renaming; production needs its own policy and qualification. No raw URLs, credentials, original bytes, or private media metadata in app-owned transfer journals/logs.

## Production qualification before declaring issues complete

| Work | Must prove | Current status |
| --- | --- | --- |
| #42 ordinary browser downloads | Origin WKWebView delegate path: attachment, non-media preview/share, site-generated blob, authenticated/session-bound response, redirect, cancellation/progress, temporary storage cleanup and lock. | **Open; implement separately.** #37 browser foundation is closed. |
| #9 session privacy | Authoritative lock/unlock, auto-lock, task-switcher exposure, and authenticated lifecycle policy. | **Open; prerequisite to #17.** |
| #17 background receipt | Locked fresh-process metadata-only recovery; .completeUnlessOpen background receipt and physical canonical .complete; actual system-initiated relaunch and force-quit semantics; timeout/resume; authenticated single-journal intake and post-commit cleanup. | **Open; tests/prototype only.** |
| #43 Save to Vault | Supported real link/media selection; iPhone/iPad direct-media UX; secure eligible transfer; media validation, progress, duplicates/quota, authenticated receipt-to-Library integration. Full unlinked-inline support stays gated; video canonical support not proven. | **Open; depends on #42 and must also be gated by #17.** |
| Release privacy | Backup exclusion, identity-only metadata outside vault, profile lifetime and no leakage across lock/relaunch, honest UI status. | **Must pass before shipping.** |

The proposed implementation order is **#42 on existing WKWebView**, **#9**, **#17**, and then **#43**; #42 and #9 may proceed independently. Before production #43, reconcile the ticket dependency graph and explicitly confirm the supported-media scope with product review. Do not close #17/#42/#43 based solely on these prototypes.
